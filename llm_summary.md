# LLM mental model — synthetic

Two high-level, non-specialist summaries of what a GPT-style LLM is and
does. The first is the author's original draft, kept verbatim. The second
is a revised version that builds on it with light corrections and a few
missing pieces, while staying synthetic and accessible.

---

## Version 1 — original

GPT-style LLMs (decoders) are next token predictors. They are trained on
huge corpus, for which they try to pick up statistical regularities : what
is the most likely next word, given previous context (tokens). Machine do
not process text very well or naturaly, so the first step before
computation is generally, converting words to numbers : that is
tokenization (one word -> on index in a vocabulary). Processing the whole
dictionary directly is not very efficient, it is better to project token
indices in a space of reduced dimension, where dimensions carry semantic
meanings (word with related meanings are close to each other) : that is
embedding. Then the attention mechanism is about the following : word
meanings is not intrinsic to the word itself but depends on other words in
the periphery. Attention computation, extracts meanings from other words
so that the meaning of each word in the "context window" is informed by
neighbors, to extract global meaning of the sentences (semantic
associations, syntax, reasoning patterns). Embedding projections or
attention computations (projection matrices, and combination/routing via
MLP architectures) are learned parameters in the complete training
exercise : they are progressively adjusted, during training, to produce
machinery (models) that are the most efficient next-token predictors :
given what patterns and statistical regularities they have observed
during training.

## Version 2 — revised

GPT-style LLMs (decoders) are next-token predictors. They are trained on
huge corpora to pick up statistical regularities: given previous context,
they output a probability distribution over the next token, and text is
generated by sampling from that distribution one step at a time.

Machines do not process text naturally, so text is first turned into
numbers — **tokenization**. GPT-2's vocabulary (~50k entries) is made of
*sub-word* units, not whole words: frequent words map to a single token,
rarer ones are assembled from pieces, so the model handles morphology and
any input rather than a fixed dictionary.

Each token id is then mapped to a vector — **embedding**. What matters in
that vector space is not the individual coordinates but *directions*:
tokens with related meanings end up close to each other, so geometry
carries semantics. Because attention by itself is order-blind, a learned
**positional encoding** is added to each token's vector so that word order
actually matters downstream.

**Attention** does the contextual part: meaning is not intrinsic, it
depends on neighbors. For each token, attention computes a weighted mix
of the other tokens' representations, producing a *contextualized* version
of that position. A **per-token MLP** follows and refines each vector
independently — attention mixes across tokens; the MLP does not. The two
alternate inside each transformer block.

These blocks are **stacked** (12 in GPT-2 small, many more in larger
models), all reading from and writing into a shared **residual stream**
that is progressively refined layer by layer. At the top, a final
projection maps each vector back to a score over the full vocabulary, a
softmax turns scores into probabilities, and one token is sampled — then
the whole loop runs again.

All of these pieces — embeddings, positional encoding, attention and MLP
projections, output projection — are learned parameters, progressively
adjusted during training to produce the most efficient next-token
predictors given the patterns and statistical regularities observed in
the training data.
